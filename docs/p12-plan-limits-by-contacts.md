# P12 套餐分层：名单规模 + 协作席位（草案定稿）

更新日期：2026-09-21。状态：迁移与设置页文案已落地；支付商品描述与 Creem/Dodo 后台需人工对齐。

## 定价原则

- **主轴**：工作区内**未归档客户**数量（用户可感知，与业务增长挂钩）。发信走用户自备 ESP，平台不按「发了多少封」对外卖流量。
- **Team 轴**：**活跃工作区成员**数（邀请接受后计入）。
- **护栏（不对价目表主打）**：`daily_send_quota`、`max_rate_per_second` 仍用于多租户公平调度与滥用防护；设置页以弱提示呈现，不强调「封/秒」。

### 「有效客户」口径

- 计入套餐：`edm.contacts.archived_at is null`（未归档）。
- 不计入：已归档客户（可归档腾出额度后再新增）。
- 退订/抑制仍占名单位（与 Mailchimp 等「联系人占库」一致）；若后续要改为「可营销联系人」计数，需单独 migration 调整计数函数。

## 档位表（与 `edm.delivery_plan_limits` seed 一致）

| plan | 对外名 | 有效客户上限 | 活跃成员上限 | 单活动收件人上限 | 日发信护栏 | 内部速率/s |
|------|--------|-------------|-------------|-----------------|-----------|-----------|
| free | Free | 500 | 1 | 500 | 1,000 | 2 |
| pro | Pro | 5,000 | 5 | 5,000 | 10,000 | 10 |
| team | Team | 25,000 | 20 | 25,000 | 25,000 | 20 |

说明：

- **单活动收件人**与**有效客户上限**对齐，避免「名单很大但每次只能发一小撮」与主轴叙事冲突。
- Pro 相对 P10 初版：收件人上限由 2,000 调整为 5,000，与 5,000 客户档一致。
- **免费版 1 名成员**：仅创建者；邀请协作者需升级 Pro。
- 典型活动耗时（对用户话术，非 SLA）：在 ESP 限速高于平台护栏时，500 人量级约 **4 分钟级**（free 内部 2/s），不必在价目表写「封/秒」。

## 触顶行为

| 场景 | 错误提示要点 |
|------|----------------|
| 新建客户 / 导入新增 | 当前套餐最多 N 位有效客户，已用 M 位 |
| 取消归档 | 同上（恢复占额度） |
| 创建成员邀请 | 当前套餐最多 N 位工作区成员 |
| 接受邀请 | 同上 |
| 确认活动 / 开始发送 | 仍沿用 P10 单活动人数与日配额护栏 |

## 设置页与升级文案

- 主行：**有效客户 M / N · 成员 A / B**。
- 次行：单活动可发至套餐上限；日发信为平台公平使用护栏（可选展开）。
- 升级弹窗：强调 **更大名单 + 团队协作**，不写「更高发信速率」。

## 与 P11 支付的关系

- 商品仍对应 `pro` / 后续 `team` → `edm.workspaces.plan`。
- Creem/Dodo 产品描述、落地页需从「发信量/速率」改为上表两列主轴；Checkout 逻辑无需改 metadata。

## 运维

```sql
-- 查看某工作区用量（需 service_role 或成员 RPC）
select edm.get_workspace_delivery_plan('{"workspace_id":"<uuid>"}'::jsonb);
```

人工升档仍可用：

```sql
update edm.workspaces set plan = 'pro' where id = '<workspace_uuid>';
```
