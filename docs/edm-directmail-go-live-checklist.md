# DirectMail 单 ESP 上线核对清单

适用站点：https://edm.contentup.cc  
预计用时：约 30 分钟（管理员账号）  
前提：`amazon_ses.enabled=false`（界面显示「Amazon SES（尚未开放）」为正常状态）

## 1. 工作区基础（设置）

| # | 操作路径 | 预期结果 |
|---|----------|----------|
| 1.1 | 设置 → 店铺信息 → 填写联系地址 → **保存设置** | 提示「工作区已保存」 |
| 1.2 | 刷新页面 | 名称与地址仍保留 |
| 1.3 | 未填联系地址时尝试开始正式发送（活动页） | 被阻断并提示先填写联系地址 |

## 2. DirectMail 通道

| # | 操作路径 | 预期结果 |
|---|----------|----------|
| 2.1 | 设置 → **添加 阿里云邮件推送** | 弹出配置对话框 |
| 2.2 | 填写发件域名、发件地址、AccessKey → **安全保存配置** | 通道卡片出现，状态「已配置，待验证」 |
| 2.3 | **发送测试邮件** | 当前管理员邮箱收到测试信，状态变为「已验证」 |
| 2.4 | （可选）开启追踪并填写 DirectMail 标签 → **保存追踪设置** | 提示追踪已开启 |
| 2.5 | （可选）**生成令牌** → 复制 Webhook 地址与令牌到阿里云 EventBridge | 界面显示已配置；首个回执后更新「最近事件」 |

## 3. 小流量正式发送

| # | 操作路径 | 预期结果 |
|---|----------|----------|
| 3.1 | 客户 → 确保至少 1–3 名「已订阅」测试收件人 | 活动预览可见样本 |
| 3.2 | 活动 → 创建草稿 → 预览 → **确认活动** | 状态为已确认 |
| 3.3 | 管理员 **开始正式发送**（输入完整活动名） | 活动进入发送中/排队 |
| 3.4 | 活动 → 统计/任务 | 任务最终为已受理或送达；若有 Webhook，回执投影更新 |

## 4. 退订闭环

| # | 操作路径 | 预期结果 |
|---|----------|----------|
| 4.1 | 从测试邮件打开退订链接 → 确认退订 | 成功页；该邮箱变为退订/抑制 |
| 4.2 | 新建活动（全员）→ 预览 | 已退订地址不在受众内或被排除计数 |

## 5. 权限与多 ESP 展示

| # | 操作路径 | 预期结果 |
|---|----------|----------|
| 5.1 | 团队 → 邀请运营或查看者登录 | 无法添加/修改通道、无法开始正式发送 |
| 5.2 | 设置 → 「即将支持」区域 | 仅显示 **Amazon SES（尚未开放）**，无「添加 Amazon SES」按钮 |
| 5.3 | 帮助 → **仅 DirectMail 上线前核对** | 与本文档一致 |

## 6. 运维侧（非 UI，发布负责人）

- [ ] content-up 已应用 P8 相关迁移（含 `p8_channel_management`）
- [ ] Edge Functions：`edm-delivery-worker`、`edm-delivery-test`、`edm-directmail-events` 等为 Active
- [ ] Cron 调用 `edm-delivery-worker`（非旧 directmail-only worker 名）
- [ ] Vercel Production 环境变量含 `EDM_CREDENTIAL_KEYRING`，与 Supabase Edge Secret 一致
